## 一、怎么审

1. 逐提交看：`git log --oneline review/mervyn-consolidated..review/fixes-1`，
   每个提交信息是「问题 / 根因 / 改动 / 测试」四段，可单独判断。
2. Revert 验证：绝大多数提交都能「回退这一处 → 对应用例变红」，提交信息里写了具体数值。
   **回退前必须 `mvn -o -q -DskipTests install`**，否则 `mvn -pl lealone-test test` 用的是
   `~/.m2` 里的旧 jar，会得到假结论（这个坑我们踩过，见台账「方法论警示」）。
3. 逐项细节（问题 / 根因 / 改动 / 验证数值 / 状态）在 [FIX_LOG.md](FIX_LOG.md)，
   下面各节只列「提交 → 解决什么问题」，方便先扫一遍再挑着看。
4. 全量与门禁：
   ```bash
   mvn -B -o -q -DskipTests install
   mvn -B -o -q -pl lealone-test test                                    # 376 项
   mvn -B -o -q -pl lealone-test test -Pslt -Dtest=SltTest \
       -Dslt.dir=/tmp/sqllogictest/test                                  # 37.6 万条查询
   ```
   需要 9210 端口上的测试服务（`TestBase` 写死了 `DEFAULT_TCP_PORT`），
   启动时把服务端 CWD 放到临时目录，否则它生成的代码会落到仓库根。

## 六、实测后判定「不改」的项（避免以后重复评估）

| 项 | 结论 |
|---|---|
| 等待循环每 20ms 调 100 次 `pump`（怀疑空转烧 CPU） | **否决**：等待 2 秒的 CPU 时间 150ms → 140ms（噪声内）；等待实际走 `scheduler.await()` |
| 每条 UPDATE 多一次 `map.put`（页锁 + 可能分裂） | **否决**：2 万次更新的耗时 95–112ms vs 95–110ms（稳态无差异） |
| 二级索引游标 `rowSnapshots` 无上界（担心大表扫描吃满堆） | **否决**：无法隔离收益（`-Xmx120m` 时插入阶段先 OOM，纯扫描瓶颈是页缓存），且加上限会牺牲去重正确性 |
| 页面写「提交重试」整页重序列化（怀疑 2 倍行拷贝） | **否决**：插桩实测重试率 **0.35%（单线程）/ 0.18%（4 线程）** |
| SLT 门禁 `rowsort` 只排实际结果不排期望值 | **改错已回退**（`a7a85a6af`）：语料期望值本就按约定排序，把期望值当扁平列表再排会打散多列行对齐，门禁失败数从 14 暴涨到 13,656 |
| `RowType` 读页面时统一补 LOB handler；`SHUTDOWN`/GC 的 `getSessionCount()` 判据 | **未采纳**：构造不出「不改就失败」的用例 / SHUTDOWN 的执行会话本身就还在，无法证明必要 |

## 七、SLT 语料的方言差异清单（判断「真 bug 还是方言」用）

门禁的 oracle 是 SQLite，以下差异是**设计使然**，不是缺陷：

| 类别 | Lealone（= H2 / 标准 SQL） | SQLite |
|---|---|---|
| `TEXT` 类型 | 映射成 CLOB → 不能建唯一索引 | 动态类型，可索引 |
| 除零 | 报错 `Division by zero` | 返回 NULL |
| 整数溢出 | 报错 `Numeric value out of range` | 64 位自动提升 |
| `COALESCE(int, AVG(...))` 参与除法 | 静态类型 → REAL 除法 | 动态类型 → 整数除法 |
| `AVG(int)` 类型 | 返回 DOUBLE（H2 兼容），类型会传播到外层表达式 | 返回 REAL，但动态类型使外层保持整数语义 |

台账里 12 条已登记的失败全部属于上表；门禁按**失败签名**比较，所以「修好一条、又坏掉一条」也能被发现。
