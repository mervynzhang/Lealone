## 一、怎么审

1. **逐提交看**：`git log --oneline review/mervyn-consolidated..review/fixes-1`，每个提交信息是
   "问题 / 根因 / 改动 / 测试"四段，能单独判断。
2. **Revert 验证**：绝大多数提交都能"回退这一处 → 对应用例变红"，提交信息里写了具体的红/绿数值。
   回退验证时**必须先 `mvn -o -q -DskipTests install`**，否则 `mvn -pl lealone-test test` 用的是
   `~/.m2` 里的旧 jar，会得到假结论（这个坑我们自己踩过，见台账"方法论警示"）。
3. **全量验证**：
   ```bash
   rm -rf lealone-test/target/test-data
   mvn -B -o -q -DskipTests install
   mvn -B -o -q -pl lealone-test test        # 368 用例
   ```
   部分用例需要 9210 端口上的服务（`TestBase` 写死了 `DEFAULT_TCP_PORT`）。

2. **`137de5658`（重复回滚守卫）已在 master 回退**，本分支把同类问题的正解放在
   `504db65a0`（事务层抛 + session 层兜）。
3. 台账里记了 **6 条方法论警示**（`install` 与 jar 解析、`executeQuery` 自动 `next()`、`mvn clean` 离线不可用、
   共享 `target/test-data`、循环重跑 SQL 要关查询缓存、共享 `~/.m2` 会被别的 agent 换掉），
   这些都是排查过程中真实吃过亏的地方。
